# schedule

Google Apps Script HTML Service 行程網站。

## 名古屋 × 大雪視覺版

以「呱旅手帖」為主題，採用霧白紙感、墨綠與朱紅配色，搭配 `WinterArt.html` 的內嵌名古屋城雪景 SVG。首頁、旅程資訊、固定導覽、每日行程、景點、餐飲與頁尾皆使用同一套冬日視覺；手機版改為單欄，保留鍵盤操作與減少動態效果設定。

部署此版本時，請同步更新 `Index.html`、`Styles.html`、`ScheduleRenderer.html`、`App.html`，並在 Apps Script 新增 **WinterArt.html**，再更新部署版本。插畫不依賴外部圖片服務。主標題、副標題與航班仍由 `settings` 控制；若要配合新主題，可將標題設定為「名古屋，大雪紀行」。雪景為主題插畫，並非即時天氣資訊。

760px 以下使用手機操作版：首頁縮為短標題搭配雪景縮圖，住宿、航班與日期預設收合，底部固定提供行程、景點、餐飲三個入口，並預留手機底部安全區。行程上方提供固定日期列，可左右滑動並直接展開、定位選定日期；既有日期卡片與地圖不會被重建，保留已展開的資料。當天依裝置本地日期比對完整年月日；今天不在行程內時，手機版預設展開第一天。行程載入失敗時隱藏日期列，其他成功讀取的區塊仍可操作。

## 景點之間的交通筆記

新增選用的 `traffic` 分頁，A 欄是交通名稱，B 欄起全部都是資訊，依同一列由左至右的順序顯示，空白欄略過。例如 A1 填「中津川站 → 馬籠宿」，B1 填乘車說明、C1 插入時刻表照片、D1 放官網連結、E1 再插入另一張照片。欄數依工作表實際使用範圍讀取。

每個資訊欄都支援儲存格內圖片、`IMAGE("圖片網址")` 公式、一般文字、貼上的網址、超連結及同一格內多個文字連結。直接貼上的 HTTP(S) 網址若有 PNG、JPG/JPEG、GIF、WebP、BMP 或 AVIF 副檔名，會當作圖片顯示；其他網址顯示為連結。沒有圖片副檔名的圖源可使用 `IMAGE()` 或儲存格內圖片。浮在儲存格上方的圖片不在讀取範圍內。

在 `schedule` 的**目的地儲存格註解（Note）**填 `traffic 1`，即可在該景點之前顯示 `traffic` 第一列的交通筆記。數字是實際列號，包含標題列；若第一列是欄位標題、資料從第二列開始，請填 `traffic 2`。也可以填 A 欄完整名稱，例如「中津川站 → 馬籠宿」；名稱比對優先於列號。名稱請保持唯一。多筆引用可分行填寫，其他未對應到資料的註解不顯示。

整段交通使用單一外框，路段名稱只顯示一次，下方並排「地圖導引」與「交通筆記」兩個獨立入口，觸控高度至少 44px。交通筆記預設收合，展開後顯示照片、補充與連結，所有內容都限制在直線右側的同一框內，不跨過時間軸；景點間的連線在收合、展開時持續保留。多張照片依欄位順序向下排列，圖片右下角以小型放大圖示提示，整張圖片都可點擊，不再逐張重複顯示放大文字。預覽可縮放、切換同筆交通的其他圖片，並按 Esc 關閉；載入失敗時仍顯示「點此重試」。同一路段的原有地圖連結整合到此框，保留原本的地點解析、載入與重試功能。沒有對應筆記的路段維持原本地圖按鈕；讀取交通資料失敗不阻止行程與地圖載入。

儲存格內圖片的原網址載入失敗時，traffic 與景點圖庫會呼叫 `getTripImage()`，重新讀取相同工作表、相同列、相同欄的原圖，並回傳圖片內容供瀏覽器顯示；仍失敗時可點擊重試。這個端點只允許此試算表 traffic 的 B 欄起與名稱以 spot 結尾工作表的 A 欄，不接受外部網址。單張重試圖片上限為 8 MB；單張圖片讀取失敗不會中斷其他行程與景點資料。原始圖片網址不快取，圖片重試也不會修改試算表或分享權限。

行程讀取新增註解，並額外讀取選用的 `traffic` 全部使用中欄位與 B 欄起的儲存格圖片；多欄原生圖片使用一次範圍讀取。下文原有的兩次批次資料請求統計不包含這個新增讀取。部署時同步更新 `Code.gs`、`ScheduleRenderer.html`、`TripRenderer.html`、`SpotGallery.html`、`Maps.html`、`Styles.html`，並更新 Apps Script 部署版本。

本機檢查：`node tests/traffic.test.cjs`，涵蓋註解、合併儲存格、批次與相容讀取、B 欄圖片、連結安全與卡片位置。Apps Script 實際授權及 Sheet 資料仍需部署後驗證。

## 自訂標題、副標題與航班

在同一份 Google Sheet 新增名為 `settings` 的分頁，A 欄填設定名稱、B 欄填顯示文字：

| A 欄 | B 欄（範例） |
| --- | --- |
| title | 岡山保佑一定好天氣 |
| subtitle | 岡山・倉敷・姬路・神戶，還有尾道的景點備忘。 |
| flights | IT714 / IT715 |

`title` 同時套用到瀏覽器標題與頁面大標題；`flights` 只填航班內容，網頁會自動加上「航班：」。
沒有 `settings` 分頁或對應值留白時，標題使用試算表名稱，副標題與航班不顯示；兩者只使用 `settings` 中填寫的內容。
設定在開啟網頁時讀取，修改 Sheet 後重新整理網頁即可；首次更新程式仍須重新部署 Apps Script 版本。
設定值以純文字輸出，不會當成 HTML 執行。

住宿也可以移到 `settings`，格式如下：

| A 欄 | B 欄（住宿名稱） | C 欄（位置） |
| --- | --- | --- |
| hotels | Dormy inn Okayama | 飯店的 Google Maps 智慧方塊或連結 |
| （留白） | Richmond Hotel Himeji | 飯店的 Google Maps 智慧方塊或連結 |

`hotels` 當列即為第一筆住宿，後續 A 欄留白可繼續新增，遇到下一個非空白設定名稱時結束。
住宿名稱與位置沿用原本 `hotel` 分頁的處理規則，支援地圖智慧方塊、超連結與純文字 Maps 網址。
有 `hotels` 設定時優先使用這份清單；未設定時繼續讀取舊的 `hotel` 分頁。
若要清空住宿，可保留 `hotels`，將其住宿區塊的 B、C 欄清空。

## 檔案職責

| 檔案 | 職責 |
| --- | --- |
| `Code.gs` | 讀取試算表、A 欄圖片與提供 HTML 範本 |

| `TripRenderer.html` | 共用文字／連結工具、住宿／餐飲渲染、整體渲染流程 |
| `ScheduleRenderer.html` | 日期與行程解析、每日卡片、展開動畫 |
| `SpotRenderer.html` | 景點解析、卡片與資訊區塊 |
| `SpotGallery.html` | 圖庫 HTML、左右切換、popup 生命週期與縮放手勢 |
| `Maps.html` | 地圖按鈕、交通路線與地圖展開動畫 |

| `WinterArt.html` | 名古屋城覆雪的原創向量插畫 |
| `SpotGalleryStyles.html` | 圖庫與 popup 樣式 |

## 載入與更新

`Index.html` 先載入共用工具、行程、圖庫、景點與地圖，最後才由 `App.html` 請求資料。
前端同時發出兩個獨立請求：`getScheduleData()` 只讀取每日行程，完成後立即顯示；`getTripDetails()` 在背景讀取景點圖片、餐飲、住宿與地圖位置。後者完成時不會重建行程卡片，保留使用者已展開的日期。兩者完成後才初始化地圖；其中一組資料讀取失敗，只顯示該區的錯誤，不清除另一組已載入的內容。

後端優先使用 Sheets API 的多範圍讀取與欄位篩選：行程只需一次 API 請求，景點、餐飲與住宿合計另一次，直接取得顯示文字、連結、公式、合併範圍與地圖智慧方塊，不再逐張表分次讀取文字／RichText／公式，也不再逐個合併儲存格讀取內容。直接插入儲存格的圖片仍需各景點表 A 欄的一次 `getValues()` 取得 `CellImage` 網址；工作表清單與使用範圍仍由 SpreadsheetApp 讀取。因此「兩次」指資料的 Sheets API 請求，並非所有 Google 服務呼叫的總數。地圖網址快取改用一次 `getAll()`，各區清單也移除尾端空白欄列以減少傳輸量，保留內部空白列的位置。

每次開啟仍直接讀取試算表，不使用行程／景點資料快取。兩個請求分開讀取，若載入途中編輯試算表，各區可能反映不同時間點的資料。舊端點 `getTripData()` 保留既有回傳格式（包含舊別名與 `spotReferences`）；新版端點不再計算或傳送這些未使用的資料。前端只保留目前使用的分段渲染函式。

Sheets API 未啟用或讀取失敗時會記錄原因並退回相容讀取，維持資料可用，但此時不會有批次讀取的效能改善。兩條路徑共用工作表探索、圖片處理與回傳資料組裝，備援時不再重新讀取工作表清單。圖片公式、智慧方塊與圖片說明使用共用解析，避免兩條路徑產生不同結果。

瀏覽器主控台會記錄「行程顯示耗時」及「其他旅遊資料顯示耗時」（從前端發出請求起算，不含 HTML 頁面本身的載入）。

Apps Script 執行記錄會標示 `Sheets API batch` 或 `compatibility reader` 與後端耗時。

景點與餐飲清單的「顯示地圖」固定在項目下方向下展開小地圖，再次點擊「隱藏地圖」收合；保留 260ms 動畫與首次展開才載入 iframe 的行為。小地圖沿用原本的地點名稱查詢，只有面板內的「在 Google Maps 開啟」連結會另開分頁。此流程與每日行程的交通路線按鈕分開初始化，不因資料中有地圖連結就改成直接跳轉。

交通路線使用景點、餐飲與住宿資料的 Google Maps 位置；優先讀取第二欄地圖連結，也支援名稱欄的地圖連結。地點智慧方塊的網址透過 Google Sheets API 的 `chipRuns.chip.richLinkProperties.uri` 讀取，以 `cell.mapUrl` 加入既有位置索引，保留原本的顯示文字與一般超連結。

初次載入的地圖智慧方塊隨其他資料一併批次取得，只取 A、B 欄作為位置來源，不連線解析地圖短網址。相容讀取路徑才另發一次 Sheets API 請求讀取 A、B 欄智慧方塊。點擊路線時才由 `resolveMapLocations()` 展開該段起終點的分享短網址，前端取出座標、Place ID 或連結內的位置查詢值。缺少可用位置時顯示「無法取得位置」；相容路徑的智慧方塊 API 也讀取失敗時顯示「地圖資料未載入」，不影響行程顯示。短網址解析失敗可點擊重試，不再用行程名稱加上「日本」搜尋。

部署前，請在 Apps Script 編輯器左側「服務」按「＋」，加入 **Google Sheets API（v4，識別碼 Sheets）**。使用 Apps Script 預設 Cloud 專案時，API 會一起啟用；若使用自訂標準 Cloud 專案，也要在該專案啟用 Google Sheets API。儲存程式、完成授權並更新部署版本後，智慧方塊內的地圖位置才會讀入。

`renderSpotSheets()` 在替換 DOM 前關閉既有 popup，完成後初始化新圖庫。
事件附加在每次建立的新元素上；不要對同一組圖庫重複呼叫 `enableSpotGalleries()`。
`closeSpotImageDialog()` 可重複呼叫，負責關閉預覽並還原頁面捲動與焦點。

部署時須將所有 HTML 檔加入 Apps Script，包括新增的四個模組檔，並更新部署版本。

此次效能修改及清理需同步更新 `Code.gs`、`App.html`、`TripRenderer.html` 與 `Styles.html`，再更新部署版本。

API 參考：[多範圍讀取與欄位篩選](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/get)、[儲存格回應格式](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/cells)、[CellImage](https://developers.google.com/apps-script/reference/spreadsheet/cell-image)。
